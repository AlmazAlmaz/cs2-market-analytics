# Установка и запуск на Windows

Проект рассчитан на 64-битную Windows 10/11 и Python 3.12. Для NVIDIA GPU
установщик использует готовую CUDA-сборку PyTorch; отдельный CUDA Toolkit и
`nvcc` не требуются.

## Первый запуск

1. Запусти двойным щелчком `setup_windows.cmd` или из `cmd.exe`:

   ```bat
   setup_windows.cmd
   ```

   Скрипт создаёт `.venv`, ставит зависимости и CUDA-сборку PyTorch, проверяет
   пакеты и GPU. Загрузка PyTorch занимает около 2 ГБ.

2. Один раз установи значок на рабочий стол и автозапуск:

   ```bat
   install_windows_launcher.cmd
   ```

   Появится значок **CS2 Dashboard**. Установка выполняется для текущего
   пользователя; права администратора не нужны. Повторная установка обновляет
   ярлыки этого проекта. После переноса папки проекта установи ярлыки заново.

   Для установки только ярлыка на рабочий стол, без изменения автозапуска:

   ```bat
   install_windows_launcher.cmd -DesktopOnly
   ```

3. Нажми **CS2 Dashboard** на рабочем столе. Также можно запустить:

   ```bat
   start_all.cmd
   ```

   Откроется небольшое окно управления. Сайт откроется автоматически после
   готовности сервисов. Повторное нажатие на значок открывает уже работающий
   экземпляр, не запуская второй набор процессов. Журналы находятся в `logs`;
   журнал запуска и остановки — `logs\launcher.log`.
   Если сервисы остановились, повторное нажатие запускает их заново, даже когда
   окно управления осталось открытым. После ошибки запуска также можно повторить
   запуск через ярлык.

4. Для остановки нажми **крестик окна CS2 Dashboard** или **Остановить**.
   Подтверждений нет: окно покажет завершение работы и закроется после остановки
   сервисов. Закрытие вкладки браузера не останавливает приложение. Кнопка
   сворачивания оставляет приложение работать в области уведомлений Windows.
   Отдельная команда остановки также доступна:

   ```bat
   stop_all.cmd
   ```

`.cmd`-обёртки обходят запрет ExecutionPolicy только для соответствующего
локального `.ps1`-процесса и не меняют системную политику PowerShell.

## Автозапуск и выключение компьютера

После установки ярлыков CS2 запускается **при входе этого пользователя в Windows**,
в фоне, со значком в области уведомлений. Браузер при автозапуске не открывается.
Чтобы открыть сайт и управление, нажми значок на рабочем столе или в области
уведомлений. До входа пользователя в Windows приложение не запускается.

При обычном выключении, перезагрузке или выходе из Windows окно управления
принимает уведомление системы и запускает ту же остановку: Python-сервисы
получают запрос завершения, обучение отменяется, соединения с базами закрываются.
Windows может кратко показать ожидание завершения CS2. Приложение не запрашивает
подтверждений и не отменяет выключение компьютера. Если выключение отменено
до подтверждения конца сеанса, сервисы продолжают работать.

Зависшим процессам даётся ограниченное время на остановку, затем применяется
проверяемое завершение только процессов этого проекта; это отмечается в журнале.
Принудительное выключение, отключение питания и принудительное завершение через
диспетчер задач не позволяют гарантировать выполнение штатной очистки. При
аварийном завершении SQLite восстанавливает незавершённые транзакции при открытии;
последние незавершённые изменения и прогресс обучения могут быть потеряны.

Чтобы убрать оба ярлыка и отключить автозапуск:

```bat
install_windows_launcher.cmd -Remove
```

Чтобы убрать только ярлык с рабочего стола, сохранив текущий автозапуск:

```bat
install_windows_launcher.cmd -Remove -DesktopOnly
```

Для прежнего консольного режима с параметрами запуска используй непосредственно
`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start_all.ps1`.
Его штатная остановка — `Ctrl+C` или `stop_all.cmd`; обработка крестика и
выключения Windows относится к новому окну **CS2 Dashboard**.

## Проверка GPU

После установки:

```bat
.venv\Scripts\python.exe -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
.venv\Scripts\python.exe gpu_smoke_test.py
.venv\Scripts\python.exe IGORMODEL\train.py --help
.venv\Scripts\python.exe train_neural_model.py --help
.venv\Scripts\python.exe train_vega_model.py --help
```

Настройки в `config.local.env`:

```dotenv
CS2_TRAINING_DEVICE=cuda
CS2_TRAINING_REQUIRE_GPU=true
CS2_CUDA_DEVICES=0
```

- Nova — нейросеть PyTorch; `auto` выбирает CUDA, затем Apple MPS, затем CPU.
- Vega — отдельная advisory-нейросеть PyTorch с feature-token Transformer. Её
  профиль рассчитан на RTX 4070 SUPER 12 ГБ: batch 2048, FP16 во время fit,
  fused AdamW (когда он доступен) и строгая FP32-проверка качества. В штатном
  режиме Vega требует CUDA и не переключается на CPU незаметно.
- Igor — CatBoost; на Windows с NVIDIA все три fit-фазы используют GPU.
- Almaz, Knives и Gloves используют `HistGradientBoostingRegressor` из
  scikit-learn. Это деревья, а не нейросети, и этот backend работает на CPU.
  Перевод их на GPU потребовал бы замены формата модели и отдельной повторной
  валидации качества.
- Создание SQLite snapshot, pandas-кэш и кодирование признаков остаются CPU/I/O
  этапами. GPU начинает загружаться на фазе непосредственного fit.

Чтобы явно разрешить CPU на машине без NVIDIA, запусти
`setup_windows.cmd -CpuOnly`. Установщик сам выставит CPU-режим и пропустит GPU smoke test.

## Переобучение моделей

Открой главную страницу dashboard и блок `Model Freshness & Quality`. У каждой
модели там есть отдельная кнопка обучения, прогресс, этапы, журнал и итог
проверки качества. Для Vega первый запуск становится доступен после накопления
не менее 100 000 корректных строк по оружейным скинам; тестовая выборка из
25 000 самых новых строк не участвует в обучении.

Vega сначала обучается в staging и не влияет на сайт. Она активируется только
если на той же неизменной тестовой выборке одновременно лучше действующей Nova
по median/mean/p90 error и проходит проверки интервалов. До первой успешной
активации отсутствие файлов Vega не мешает запуску проекта. После появления
active pointer лаунчер строго проверяет SHA-256 всего поколения и выполняет
runtime smoke; повреждённая или неполная модель не будет загружена.

В прогнозах Vega показывается как четвёртое advisory-мнение. Она не меняет
старые правила `all three agree`, `unanimous_three` и выбор консервативного
прогноза по Almaz/Igor/Nova.

## Сканер выгодных предложений

На главной странице открой вкладку управления системой и блок сканера.
Выбери профиль: оружие со стикерами, недорогие ликвидные скины, ножи или
перчатки. У каждого профиля отдельно сохраняются режим выбора, число целей
за цикл и число лотов на цель.

- В режиме «Рекомендованные» можно добавлять свои цели и исключать отдельные
  предметы. В режиме «Свой список» участвуют только выбранные цели и группы.
- Наклейки можно выбирать целым турниром, включая быстрый выбор Katowice
  2014 + 2015. Отдельный флажок позволяет исключить наклейку из выбранной группы.
- Переключатели «Все / Выбраны / Не выбраны» относятся к текущей странице
  списка. Поиск по названию ищет по локальному каталогу. После правок нажми
  «Сохранить профиль»: сканер применит их на границе следующего цикла.
- Интервал `0` запускает циклы подряд; положительный интервал задаётся от
  одной минуты. Ограничения API и ожидание сброса квот действуют в обоих режимах.

Найденные предложения находятся на странице «Сделки» (`/deals`). Там есть
быстрые фильтры, поиск, выбор модели (включая Vega), типа предмета и источника
находки. Дополнительные фильтры задают цену, безопасную прибыль/ROI, ликвидность,
float, стоимость стикеров и свежесть. Активные фильтры видны над результатами;
их можно убрать по одному или сбросить вместе. Выбор сохраняется в адресе
страницы, поэтому ссылку можно сохранить в закладки.

Фильтр Vega показывает предложения с её положительной оценкой, если есть хотя
бы один положительный сигнал основной модели. Правило согласия Almaz/Igor/Nova
и расчёт консервативной прибыли остаются прежними. Для ножей и перчаток
показываются оценки соответствующих отдельных моделей.

Для ускорения сканера общая подготовка признаков выполняется один раз на лот,
а справочники категорий моделей переиспользуются. Каталог целей загружает типы
скинов пакетами; список групп наклеек кэшируется на 30 секунд. Скорость полного
цикла также зависит от числа выбранных целей, лотов и доступной квоты API.

После обновления файлов перезапусти проект через `stop_all.cmd` и
`start_all.cmd`, затем обнови страницу браузера.

## Запуск только сайта

Для проверки интерфейса без parser/scanner/Trend/VPS:

```bat
set START_PARSER=0
set START_SCANNER=0
set START_TREND=0
set START_MARKET_HISTORY=0
set START_REVERSE_TUNNEL=0
set START_API=0
set START_TELEGRAM=0
start_all.cmd
```

Сервисные PID и проверяемые Windows process-state файлы хранятся в `.run`.
Повторный launcher не запускает второй комплект процессов, а `stop_all.cmd`
проверяет PID, время создания и командную строку supervisor перед остановкой.

## Постоянный публичный домен через VPS

Для домена `https://csskinsprediction.online` заполни отдельный приватный файл
`hosting.local.env`. Можно указать SSH-ключ (рекомендуется) или существующий
пароль VPS:

```dotenv
VPS_HOST=IP_СЕРВЕРА
VPS_USER=root
VPS_SSH_PORT=22
VPS_IDENTITY_FILE=
VPS_PASSWORD=ПАРОЛЬ_СЕРВЕРА
REMOTE_BIND_HOST=127.0.0.1
REMOTE_PORT=8010
LOCAL_HOST=127.0.0.1
LOCAL_PORT=8010
PUBLIC_SITE_URL=https://csskinsprediction.online
```

После этого обычный `start_all.cmd` поднимет reverse SSH автоматически. На
Windows пароль передаётся штатному `ssh.exe` через `SSH_ASKPASS`: он не
добавляется в аргументы процесса, PID-state или журналы. Переменные askpass
устанавливаются только на время запуска `ssh.exe`, а сам ssh наследует лишь
путь к защищённому `hosting.local.env`. Файл должен оставаться приватным;
`setup_windows.cmd` ограничивает его ACL текущим пользователем, SYSTEM и
администраторами.

Если одновременно заполнены `VPS_IDENTITY_FILE` и `VPS_PASSWORD`, используется
ключ. При публичном ответе `502` сначала проверь локальный dashboard и журнал
туннеля:

```bat
curl.exe -fsS http://127.0.0.1:8010/health
type logs\reverse_tunnel.error.log
curl.exe -fsS https://csskinsprediction.online/health
```

Остановка CS2 Dashboard, выключение ПК или переход Windows в сон разрывают
туннель. Окно управления можно свернуть в область уведомлений. Лаунчер блокирует
сон и автоматически переподключает SSH, пока работает; при штатном завершении
ограничение сна снимается.
